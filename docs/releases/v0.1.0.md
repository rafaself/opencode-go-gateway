# OpenCode Gateway v0.1.0

## Supported use case

OpenCode Gateway lets Codex CLI use models available through an OpenCode Go
subscription. The v0.1.0 path translates streaming Codex Responses traffic to
OpenCode Go Chat Completions for `deepseek-v4-flash`, then translates the
provider stream back to Codex Responses events.

The project is independent from OpenCode CLI and is not affiliated with or
endorsed by OpenAI, OpenCode, DeepSeek, or the Codex CLI maintainers.

## Baseline and assets

- Tested Codex CLI baseline: `0.146.0`.
- Go source requires Go `1.22` or newer.
- Published targets: Linux amd64/arm64, macOS amd64/arm64, and Windows amd64.
- Every archive includes the platform binary, `LICENSE`, and minimal
  `README.txt`.
- `SHA256SUMS` contains SHA-256 checksums for every archive.

## Setup

1. Download the archive for the operating system and architecture, verify its
   checksum, and extract it.
2. Keep `OPENCODE_GO_API_KEY` in the gateway process environment only.
3. Start `opencode-gateway run`.
4. Run `opencode-gateway setup codex` and then `opencode-gateway doctor`.

The full procedure is in [the README](../../README.md),
[Codex setup](../codex-setup.md), and [the release guide](../release.md).

## Known limitations

- The release implements the tested streaming Responses subset, not the full
  OpenAI Responses API.
- The provider path is currently `deepseek-v4-flash`; model catalog metadata is
  generated for that compatibility path.
- `namespace` and `web_search` metadata is non-executing; unsupported custom
  tools and deferred capabilities fail closed.
- `apply_patch` is transported but never executed or applied to a filesystem.
- Pending tool-result continuation state is bounded and process-local; a
  restart loses it.
- The default service is local and loopback-only. Non-loopback binding is an
  explicit, unauthenticated opt-in.
- CI and this release workflow do not make paid inference requests.

## Compatibility caveat

The checked-in contract is based on Codex `0.146.0` on Linux amd64. Other Codex
versions and native macOS/Windows behavior are not implied by that row. If
Codex changes its request fields, config schema, or event ordering, recapture
in an isolated home and update `testdata/codex/field-policy.json` and the
compatibility matrix before treating the version as supported.

## Required RC gate

Run `make release-check`, `make package-self-test`, the isolated setup/doctor
and health procedure in [release.md](../release.md), and verify every archive
against `SHA256SUMS`. Confirm `version` and `help` output, restrictive config
permissions, absence of credentials from files/logs, and clean rollback.

Real text, standard function-tool, `apply_patch`, and continuation smoke runs
are separate opt-in gates. This release note must not be read as claiming that
unavailable paid text/tool/apply-patch smoke was run. The safe recapture steps
are in [codex-compatibility.md](../codex-compatibility.md).
